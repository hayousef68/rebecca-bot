## 📦 نصب، حذف و آپدیت

### نصب (تک‌خطی)

```bash
bash <(curl -Ls https://raw.githubusercontent.com/hayousef68/rebecca-bot/main/install.sh)
```

در پایان نصب آدرس وب‌پنل، نام کاربری و رمز تصادفی نمایش داده می‌شود. بعد در تلگرام `/start` بزنید و پنل ربکا را وصل کنید (از ربات، یا وب‌پنل > تنظیمات).

### نصب بدون سؤال

```bash
BOT_TOKEN=123456:ABC... ADMIN_ID=111111,222222 WEB_USER=admin WEB_PASSWORD=mypass1234 WEB_PORT=8686 \
bash <(curl -Ls https://raw.githubusercontent.com/hayousef68/rebecca-bot/main/install.sh)
```

| متغیر | معنی |
|---|---|
| `BOT_TOKEN` | توکن ربات از BotFather |
| `ADMIN_ID` | شناسه عددی ادمین‌ها، جدا شده با کاما |
| `WEB_USER` / `WEB_PASSWORD` | نام کاربری و رمز وب‌پنل |
| `WEB_PORT` | پورت وب‌پنل (پیش‌فرض `8686`) |

### آپدیت

```bash
rebecca-bot update
```

تنظیمات (`config.json`) حفظ می‌شود. اگر پورت عوض شد:

```bash
systemctl restart rebecca-webapp rebecca-bot
```

### حذف

```bash
bash <(curl -Ls https://raw.githubusercontent.com/hayousef68/rebecca-bot/main/install.sh) uninstall -y
```

برای نگه داشتن تنظیمات: `uninstall -y --keep-config`

**مسیر نصب:** `/opt/rebecca-bot` · **دستور سراسری:** `/usr/local/bin/rebecca-bot`
**سرویس‌ها:** `rebecca-bot` (ربات) و `rebecca-webapp` (وب‌پنل)

## 🔌 اتصال به پنل ربکا

دو بخش جدا دارد:

**۱. اتصال API (برای ساخت و مدیریت کاربر):** از ربات (🖥 پنل‌ها) یا وب‌پنل (تنظیمات > پنل‌های ربکا). آدرس پنل، دامنه ساب (اختیاری)، نام کاربری و رمز ادمین پنل را بدهید. بعد از ذخیره، اتصال تست می‌شود.

**۲. اتصال دیتابیس (برای گزارش فروش و تاریخچه قدیمی):** در ربات بزنید:

```bash
/setdb 127.0.0.1 3306 user pass dbname
```

نمونه با مقادیر فرضی:

```bash
/setdb 127.0.0.1 3306 rebecca YOUR_DB_PASSWORD rebecca
```

> ⚠️ رمز دیتابیس واقعی را هیچ‌وقت داخل ریپوی عمومی یا README نگذارید. اگر قبلاً گذاشته‌اید، آن رمز را در MySQL عوض کنید.

بدون این اتصال، گزارش فروش و تاریخچه رویدادهای قبل از ثبت محلی کار نمی‌کند. بقیه امکانات روی API پنل کار می‌کنند.

### چند پنل

هر تعداد پنل اضافه کنید. موقع ساخت اکانت پنل مقصد را انتخاب می‌کنید. تمپلت‌ها بین همه پنل‌ها مشترک‌اند و سرویس‌ها برای هر پنل جدا خوانده می‌شوند. «پنل فعال» برای جستجو، لیست، آمار و پاکسازی استفاده می‌شود.

## 🤖 ربات تلگرام

فقط ادمین‌های تعریف‌شده (`ADMIN_ID`) به ربات دسترسی دارند. بقیه شناسه عددی خودشان را می‌بینند.

### دستورات

| دستور | کار |
|---|---|
| `/start` | منوی اصلی |
| `/report` | گزارش فروش لحظه‌ای امروز |
| `/setdb` | اتصال دیتابیس پنل |
| `/cancel` | لغو عملیات جاری |

### منوی اصلی

| دکمه | کار |
|---|---|
| ⚡ ساخت سریع | ساخت با تمپلت فعال |
| 🎯 ساخت با انتخاب تمپلت | انتخاب تمپلت، پنل و سرویس، بعد ساخت |
| 🔍 جستجو و مدیریت کاربر | جستجو با نام و مدیریت همان کاربر |
| 📋 لیست کاربران | لیست صفحه‌بندی‌شده |
| ⚙️ تمپلت‌ها | ساخت، ویرایش، حذف و فعال‌کردن تمپلت |
| 📊 وضعیت سرور | آمار منابع و کاربران پنل |
| 🧹 پاکسازی منقضی‌ها | حذف دسته‌ای کاربران منقضی |
| 📥 خروجی لینک‌ها | فایل txt از همه لینک‌ها |
| 📈 گزارش فروش امروز / دیروز | گزارش فروش |
| 🖥 پنل‌ها | افزودن، فعال‌کردن، ویرایش، حذف پنل |
| 🗄 اتصال دیتابیس | همان `/setdb` به‌صورت مرحله‌ای |

### ساخت گروهی

نام پایه + عدد شروع + تعداد:

| ورودی | نتیجه |
|---|---|
| `ali` | یک کاربر به نام `ali` |
| `ali 1 10` | ده کاربر: `ali1` تا `ali10` |

سقف هر دسته ۲۰۰ کاربر است (`max_batch`). QRها در آلبوم‌های ۱۰تایی ارسال می‌شوند (سقف `max_qr` = ۱۰۰) و یک فایل txt از همه لینک‌ها هم می‌آید. با دکمه 🖼 می‌توانید ارسال QR را خاموش کنید و فقط لینک بگیرید.

### کارت کاربر در ربات

🖼 QR · ✏️ ویرایش (حجم و روز) · 🔄 صفر کردن مصرف · 🔗 لینک جدید · ⛔/✅ فعال یا غیرفعال · 🗑 حذف (با تأیید) · ↩️ برگشت آخرین تمدید یا ریست

## 🌐 وب‌پنل ادمین

آدرس: `http://IP:8686` (یا https اگر SSL فعال باشد). پنج تب اصلی دارد:

### ➕ ساخت
ساخت گروهی اکانت: پنل، تمپلت، سرویس، نام پایه، شروع و تعداد. گزینه‌های ارسال QR به تلگرام و ثبت به‌عنوان «واریز نشده». می‌توانید کاربران ساخته‌شده را همان لحظه به یک نماینده نسبت بدهید.

### 👥 کاربران
جستجو، فیلتر وضعیت (فعال، On-Hold، منقضی، محدود‌شده، غیرفعال، نامحدود) و کارت قابل‌بازشدن برای هر کاربر. جزئیات در بخش [مدیریت کاربر](#-مدیریت-کاربر).

### 🏠 خانه
- آمار کاربران (کل، فعال، آنلاین، On-Hold، منقضی، محدود، غیرفعال)
- 🖥 منابع سرور
- 📈 گزارش فروش امروز، دیروز، ماه‌های شمسی و بازه دلخواه، همراه با ویرایش تک‌تک فروش‌ها
- 📐 حجم‌های خارج از لیست قیمت
- عملیات: پاکسازی منقضی‌ها، ریستارت هسته

### 📋 تمپلت
هر تمپلت: نام، نوع (تکی یا همکاری)، حجم (`0` = نامحدود)، روز (`0` = نامحدود)، حالت شروع (`on_hold` یا `active`) و قیمت (برای فروش به نماینده).

### ⚙️ تنظیمات
منوی کشویی با این بخش‌ها:

| بخش | محتوا |
|---|---|
| 🖥 پنل‌های ربکا | افزودن، ویرایش، تست اتصال، فعال‌سازی، حذف |
| 🤖 ربات تلگرام | توکن و ادمین‌ها |
| 🔔 اعلان‌های هوشمند | چهار هشدار قابل روشن و خاموش (پایین‌تر) |
| 🩺 سلامت سیستم | وضعیت پنل‌ها، دیتابیس، سرویس، بکاپ، دیسک، کیف پول‌ها و امنیت |
| 🛡 امنیت ورود | ورود دومرحله‌ای، آستانه کد برای مبلغ بالا، تلاش‌های اخیر ورود |
| 🧾 لاگ فعالیت | Audit با فیلتر، جستجو و CSV |
| 🆕 کاربر جدید | پیشوند پیش‌فرض نام (مثل `MS_`) |
| 💸 تمدید واریز نشده | مهلت به ساعت |
| 👤 نماینده‌ها | مدیریت کامل نماینده‌ها |
| 💰 قیمت‌ها و فروش | قیمت همکاری، لیست قیمت تکی، هزینه |
| 💾 بکاپ و بازیابی | تنظیم و بازیابی بکاپ |
| 🔒 SSL و پورت | گواهی، دامنه، پورت وب‌پنل |
| 🔑 رمز وب‌پنل | تغییر رمز |

## 👤 مدیریت کاربر

کارت هر کاربر در وب‌پنل شامل وضعیت، نوار مصرف، حجم و اعتبار باقی‌مانده، لینک ساب و دکمه‌های 🖼 QR، 📋 لینک، 💬 پیام آماده، 🔄 ریست و 📜 تاریخچه است. چهار زبانه دارد:

### ⚡ تمدید
- تمدید با تمپلت یا با حجم و روز دلخواه
- انتخاب اینکه مصرف قبلی صفر شود یا حفظ شود
- انتخاب حالت `on_hold` یا `active`
- گزینه «واریز نشده» (مهلت پرداخت)

### ✏️ ویرایش
- تغییر حجم و روز (مقدار جدید)
- یا **افزودن** حجم و روز به مقدار فعلی بدون صفر شدن مصرف
- تغییر سرویس و یادداشت پنل

### 🔁 پلن بعدی
صف پلن بعدی برای کاربر. وقتی حجم یا زمان فعلی تمام شد، پلن بعدی خودکار شروع می‌شود. دو حالت محاسبه:

| حالت | معنی |
|---|---|
| `chain` (پیش‌فرض) | N روز بعد از پایان اشتراک فعلی |
| `duration` | N روز از لحظه ذخیره |

### ⋯ بیشتر
🔗 لینک جدید (لینک قبلی از کار می‌افتد) · ⛔/✅ فعال یا غیرفعال · 🗑 حذف

### ↩️ برگشت تمدید یا ریست اشتباهی
قبل از هر تمدید یا ریست، وضعیت کاربر در فایل محلی `renew_undo.json` نگه داشته می‌شود. دکمه «برگشت» حجم باقی‌مانده، مدت، وضعیت و پلن‌های بعدی را به حالت قبل برمی‌گرداند و آن تمدید از گزارش فروش حذف می‌شود. به پنل بار اضافه نمی‌دهد.
پیش‌فرض: نگهداری ۳۰۰ نقطه برای ۱۴ روز؛ ریست دسته‌ای بزرگ‌تر از ۳۰ کاربر عکس‌برداری نمی‌شود.

### 💸 تمدید واریز نشده
تمدید را با علامت «واریز نشده» ثبت کنید. اگر تا پایان مهلت (پیش‌فرض ۲۴ ساعت) دکمه «✅ واریز شد» زده نشود، اشتراک خودکار غیرفعال می‌شود.

### 📜 تاریخچه
با باز کردن گزینه «📜 تاریخچه» در کارت کاربر (ادمین و نماینده) لیست رویدادها، جدیدترین اول، با تاریخ و ساعت شمسی نشان داده می‌شود:

🆕 ساخت اکانت · 🔄 تمدید یا ریست · ➕ افزودن حجم · 🔁 پلن بعدی

- رویدادهای جدید در فایل `user_history.json` ثبت می‌شوند (همراه حجم و مدت پلن).
- رویدادهای قدیمی‌تر، اگر دیتابیس پنل وصل باشد، از آن خوانده می‌شوند (بدون حجم و مدت).
- نماینده فقط تاریخچه کاربرهای خودش را می‌بیند.
- ثبت تاریخچه جدا از عملیات مالی است و خطای آن روی ساخت و تمدید اثر نمی‌گذارد.

## 🤝 نماینده‌ها و کیف پول

### ساخت نماینده (وب‌پنل > تنظیمات > نماینده‌ها)
نام کاربری، رمز و نام نمایشی را بدهید. پیام ورود آماده کپی می‌شود (رمز فقط یک بار نشان داده می‌شود). نماینده از همان صفحه ورود وارد می‌شود و فقط پنل مخصوص خودش را می‌بیند.

### ابزارهای ادمین برای هر نماینده

| ابزار | توضیح |
|---|---|
| افزودن یا حذف کاربر از لیست | با بازه (`MS_111` تا `MS_150`) یا لیست نام‌ها |
| 💰 کیف پول | شارژ یا کسر دستی با توضیح، و دفتر تراکنش‌ها |
| 🧩 تمپلت‌های فعال | فقط تمپلت‌های دارای قیمت قابل خرید برای نماینده |
| 🔁 دسترسی پلن بعدی | اجازه افزودن پلن بعدی با کیف پول (حداکثر ۳ پلن در صف) |
| پنل مقصد | پنلی که نماینده روی آن اکانت می‌سازد |
| رمز | دستی یا تصادفی؛ رمز قبلی را از کار می‌اندازد و قفل را برمی‌دارد |
| ⛔ مسدودسازی | نماینده همان لحظه بیرون انداخته می‌شود |
| 🗑 حذف | کاربرهای پنل ربکا حذف نمی‌شوند |

### پنل نماینده

| بخش | کار |
|---|---|
| ➕ ساخت اکانت | خرید با تمپلت از موجودی کیف پول، با نام خودکار طبق شماره‌گذاری پنل، یادداشت و علامت «پرداخت شد» |
| 👥 کاربران من | جستجو، لینک، QR، اشتراک‌گذاری، یادداشت (اسم مشتری)، فعال یا غیرفعال کردن، تغییر لینک، تمدید با کیف پول، پلن بعدی (در صورت دسترسی)، 📜 تاریخچه |
| 💳 کیف پول | موجودی، فروش روزانه ۷ روز اخیر، جزئیات فروش امروز، تراکنش‌ها، درخواست افزایش موجودی |

نماینده یادداشت پنل (مخصوص ادمین) را نمی‌بیند؛ یادداشت او جداست.

### درخواست افزایش موجودی
نماینده مبلغ و توضیح را ثبت می‌کند. ادمین در تنظیمات می‌تواند **تأیید و شارژ** یا **رد** کند. مبلغ قابل اصلاح است.

### حفاظت مالی
- هر خرید و تمدید یک شناسه یکتا دارد؛ کلیک تکراری یا قطع شبکه باعث کسر دوباره نمی‌شود.
- اگر عملیات روی پنل شکست بخورد، مبلغ خودکار برمی‌گردد.
- موجودی منفی مجاز نیست.
- شارژ، کسر یا تأیید بالاتر از آستانه (پیش‌فرض ۲ میلیون تومان)، با ورود دومرحله‌ای کد جداگانه می‌خواهد.
- هر ۶ ساعت تطابق مالی بررسی می‌شود و اختلاف به ادمین اطلاع داده می‌شود.
- ۵ بار رمز اشتباه پیاپی، حساب نماینده را قفل می‌کند و به ادمین پیام می‌رسد. با «🔓 فعال‌سازی مجدد» یا `rebecca-bot unlock --rep نام` باز می‌شود.

## 🛒 فروشگاه (ربات فروش مشتری)

یک ربات تلگرام **جدا** برای مشتری‌های خودتان که داخل همان پروسه‌ی ربات مدیریت اجرا می‌شود (سرویس جدید لازم نیست).

### راه‌اندازی
1. در BotFather یک ربات **جدید** بسازید.
2. در ربات مدیریت بزنید: `/setshop TOKEN` (پیام حاوی توکن پاک می‌شود). خاموش کردن: `/setshop off`
3. داخل **ربات فروش** بزنید `/start` و بعد `/admin`:
   - 💳 **کارت**: شماره کارت، نام صاحب کارت و بانک
   - 📦 **پلن‌ها**: یک تمپلت انتخاب کنید و قیمت بدهید (حجم و مدت از خود تمپلت می‌آید)
   - 🖥 **پنل فروش**: پنلی که اکانت مشتری‌ها روی آن ساخته می‌شود (پیش‌فرض: پنل فعال)
   - ✏️ متن خوش‌آمد و پشتیبانی

> ادمین‌ها (`ADMIN_ID`) باید یک‌بار در ربات فروش `/start` بزنند تا رسیدها برایشان بیاید.

### مشتری چه می‌کند
| بخش | کار |
|---|---|
| 🛒 خرید کانفیگ | انتخاب پلن ← پرداخت از **کیف پول** (آنی) یا **کارت‌به‌کارت** (عکس رسید) |
| 👛 کیف پول | شارژ با رسید کارت‌به‌کارت، تاریخچه تراکنش |
| 🔄 سرویس‌های من | مصرف، اعتبار، لینک، QR و تمدید (کیف پول یا رسید) |
| 🧾 سفارش‌های من | وضعیت هر سفارش، لغو سفارشِ منتظر رسید |
| 📢 عضویت اجباری | تا ۵ کانال (عمومی یا خصوصی با لینک دعوت)؛ مشتری تا عضو نشود به هیچ بخشی دسترسی ندارد و با «✅ عضو شدم» دوباره بررسی می‌شود. ربات فروش باید ادمین کانال باشد (وگرنه آن کانال نادیده گرفته می‌شود و به ادمین‌ها هشدار می‌رسد). ادمین‌ها معاف‌اند. تنظیم: وب‌پنل > فروشگاه > ربات. |
| 🎁 تست رایگان | هر مشتری فقط **یک‌بار** (ثبت اتمیک؛ دوبار زدن = یک اکانت). از وب‌پنل (فروشگاه > ربات > تست رایگان) روشن و تمپلت و پیشوند نام کاربری انتخاب می‌شود. اگر ساخت قطعاً شکست بخورد حق تست برمی‌گردد؛ اگر مبهم بود ادمین خبر می‌شود و در تب مشتری‌ها «بازنشانی تست» می‌زند. تست قابل تمدید است. |
| 🔗 اتصال سرویس قبلی | مشتری **لینک ساب** سرویس قدیمی‌اش را می‌فرستد؛ ربات با پنل تطبیق می‌دهد (توکن لینک باید دقیقاً با توکن کاربر در پنل یکی باشد) و سرویس به «سرویس‌های من» اضافه می‌شود تا تمدید شود. سرویسی که به مشتری دیگری وصل است پذیرفته نمی‌شود. لینک را می‌شود بدون زدن دکمه هم مستقیم فرستاد. |

**بدون تایپ:** دکمه‌ی دائمی «🏠 منوی اصلی» پایین صفحه، دکمه‌ی منوی دستورات کنار فیلد پیام (`/start` و برای ادمین `/admin`) و دکمه‌ی START روی صفحه‌ی اول ربات (با توضیحات) خودکار تنظیم می‌شود.

### ادمین چه می‌کند
- رسید با عکس برای همه‌ی ادمین‌ها می‌آید؛ دکمه‌ی **✅ تأیید** اکانت را می‌سازد و لینک و QR را برای مشتری می‌فرستد، **❌ رد** با یکی از دلیل‌های آماده.
- `/admin`: رسیدهای در انتظار، سفارش‌های ناموفق، جستجوی مشتری (شارژ، کسر، مسدودسازی)، پلن‌ها، کارت، باز و بسته کردن فروشگاه.

### حفاظت مالی
- هر سفارش شناسه‌ی یکتا دارد و فقط یک‌بار «تأیید» می‌شود (دو ادمین هم‌زمان = فقط یکی اثر می‌کند).
- کسر کیف پول و ثبت سفارش یک عملیات اتمیک است؛ شارژ، کسر و بازگشت وجه با شناسه‌ی تراکنش یکتا ثبت می‌شود و تکرار اثری ندارد.
- ساخت اکانت اگر **قطعاً** شکست بخورد، پرداخت با کیف پول خودکار برمی‌گردد. اگر نتیجه مبهم باشد (مثلاً قطع اتصال وسط کار) پولی جابه‌جا نمی‌شود و سفارش به «ناموفق» می‌رود؛ ادمین **🔁 تلاش مجدد** (اکانتِ ساخته‌شده دوباره ساخته نمی‌شود) یا **💰 اعتبار به کیف پول** را می‌زند.
- یک عکس رسید فقط برای یک سفارش پذیرفته می‌شود؛ هر مشتری حداکثر ۳ سفارش باز دارد؛ سفارشِ بی‌رسید بعد از ۲۴ ساعت لغو می‌شود؛ رسیدِ بررسی‌نشده بعد از ۳ ساعت یادآوری می‌شود.
- داده‌ی فروشگاه (مشتری‌ها، موجودی، سفارش‌ها) داخل `config.json` است؛ پس بکاپ شامل آن است و «بازیابی فقط تنظیمات» آن را دست‌نخورده نگه می‌دارد.
- اکانت‌های فروشگاه با همان یوزر API پنل ساخته می‌شوند؛ اگر آن یوزر ادمین اصلی (`admin`) باشد، در گزارش فروش روزانه هم شمرده می‌شوند.

## 📈 گزارش فروش

هر شب ساعت **۰۰:۰۰ به وقت ایران** گزارش روز به ادمین‌ها در تلگرام می‌آید. `/report` یا دکمه «گزارش امروز» گزارش لحظه‌ای می‌دهد. گزارش مستقیم از دیتابیس پنل خوانده می‌شود:

| رویداد | منبع |
|---|---|
| ساخت کاربر | `users.created_at` |
| ریست یا تمدید | `user_usage_logs.reset_at` |
| تمدید بدون ریست، افزودن حجم، پلن بعدی | فایل محلی `attach_log.json` |

### محاسبه قیمت
- **همکاری (Hamkari):** حجم × قیمت هر گیگ (`hamkari_per_gb`)
- **تکی:** از لیست `single_prices` (حجم + مدت)؛ برای حجم خارج از لیست، نرخ جایگزین محاسبه می‌شود
- سرویس‌های نادیده‌گرفته‌شده (مثل `test`) در فروش حساب نمی‌شوند

### ویرایش دستی فروش
در وب‌پنل (خانه > گزارش فروش) هر فروش را می‌توانید **حذف**، **برگردانی** یا **ویرایش** (حجم، مدت، نوع) کنید. این تغییرات در `sales_overrides.json` ذخیره می‌شود و به پنل یا دیتابیس دست نمی‌زند، پس هر لحظه برگشت‌پذیر است.

### تنظیمات `sales` در `config.json`

| کلید | معنی |
|---|---|
| `hamkari_per_gb` | قیمت هر گیگ همکاری |
| `buy_per_tb` / `tb_gb` | هزینه خرید هر ترابایت |
| `hamkari_usage_multiplier` | ضریب مصرف همکاری (پیش‌فرض ۱٫۵) |
| `single_prices` | لیست قیمت تکی |
| `hamkari_service_names` / `hamkari_service_ids` | تشخیص سرویس همکاری |
| `ignore_service_names` | سرویس‌های نادیده‌گرفته‌شده |
| `fallback_plan_gb` | حجم مبنا برای نرخ جایگزین |
| `attach_extra_mode` | رفتار افزودن حجم خارج از لیست |
| `db_tz_offset_minutes` | اختلاف ساعت دیتابیس با UTC |

بیشتر این‌ها از وب‌پنل (تنظیمات > قیمت‌ها و فروش) هم قابل ویرایش‌اند.

## 💾 بکاپ و بازیابی

- بکاپ خودکار در تلگرام برای ادمین‌ها: پیش‌فرض روزانه ساعت ۱۲:۰۰، یا هر N دقیقه (فقط وقتی چیزی تغییر کرده)
- 🔐 رمز بکاپ اختیاری (فایل رمزنگاری می‌شود)
- ☁️ بکاپ آنلاین (Live) به یک چت یا ربات جدا، بدون پیام تکراری
- دکمه ارسال فوری بکاپ، پیش‌نمایش بازیابی و بازیابی از فایل
- اعتبارسنجی بکاپ و هشدار در صورت شکست ارسال

بکاپ شامل تنظیمات، نماینده‌ها، کیف پول‌ها و لاگ Audit است.

🛒 **فروشگاه هم کامل داخل بکاپ است:** همه‌ی کاربران ربات فروش، موجودی کیف پول، سرویس‌ها، سفارش‌ها و دفتر تراکنش‌ها. تعداد مشتری‌ها و جمع موجودی آن‌ها در کپشن هر بکاپ تلگرام، «بررسی سلامت بکاپ» و پیش‌نمایش بازیابی نمایش داده می‌شود. روی سرور تازه همه چیز از بکاپ برمی‌گردد؛ روی سرور فعال، «فقط تنظیمات» موجودی فعلی مشتری‌ها را حفظ می‌کند و «بازیابی کامل» آن‌ها را از بکاپ برمی‌گرداند.

## 🛡 امنیت

| مورد | توضیح |
|---|---|
| رمز وب‌پنل | هش‌شده (PBKDF2) در `config.json` با دسترسی `600`، نه داخل کد |
| ورود دومرحله‌ای (2FA) | با اپلیکیشن Authenticator، همراه کدهای بازیابی |
| قفل نماینده | بعد از ۵ رمز اشتباه |
| لاگ ورود | تلاش‌های موفق و ناموفق با IP |
| درخواست‌های تغییردهنده | نیاز به هدر `X-Requested-With` (حفاظت CSRF) |
| SSL | از تنظیمات یا CLI؛ اگر گواهی خراب باشد وب‌پنل روی http بالا می‌آید و علت نمایش داده می‌شود |

**توصیه‌ها**
- وب‌پنل را پشت HTTPS (Nginx یا Caddy) بگذارید یا پورت را فقط برای IP خودتان باز کنید.
- 2FA را روشن کنید.
- هیچ توکن یا رمزی را در ریپوی عمومی نگذارید.
- اگر موبایل 2FA را از دست دادید: `rebecca-bot twofa off`
